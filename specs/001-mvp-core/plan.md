# Implementation Plan: MVP Core — Multi-Project Expense Tracker

**Branch**: `001-mvp-core` | **Date**: 2026-05-01 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-mvp-core/spec.md`

## Summary

App web responsive (PWA) que reemplaza el Excel de tracking de gastos del usuario, soportando múltiples proyectos por workspace, multi-currency (ARS/USD) con FX snapshot inmutable, workspaces personales y compartidos para familia/pareja, dashboard con totales y distribuciones, búsqueda + filtros con persistencia URL, import desde Excel template y export CSV.

**Approach técnico**: Next.js 15 App Router con React Server Components para lecturas iniciales, Server Actions para mutaciones, TanStack Query con `useOptimistic` para feedback instantáneo. Supabase Postgres con RLS workspace-scoped desde el día 1, Auth con magic link + email/pw, Storage para attachments. FX rate fetched diariamente desde dolarapi.com vía Edge Function. Tailwind v4 + shadcn/ui + Tremor para charts. next-intl para es/en. next-pwa para instalabilidad. SheetJS para Excel I/O. Deploy en Vercel.

## Technical Context

**Primary Dependencies**: Next.js 15 (App Router, RSC, Server Actions), React 19, Tailwind v4, shadcn/ui, TanStack Query v5, Zustand, React Hook Form, Zod, @supabase/ssr, next-intl, next-pwa, SheetJS, @tremor/react + recharts, date-fns, lucide-react, sonner

**Testing**: Vitest (utils + Server Actions), Playwright (smoke E2E v1.1), Testing Library (componentes críticos)
**Target Platform**: Web responsive (Chrome/Safari/Firefox modernos) instalable como PWA en iOS Safari, Chrome Android, Chrome desktop
**Project Type**: Web application monolítica (single Next.js project con Server Actions reemplazando backend separado)
**Performance Goals**:
- TTI mobile 4G < 2.5s en dashboard con 1000 gastos
- Mutación de gasto end-to-end < 2s en 4G
- Búsqueda full-text < 500ms con 5000 gastos

- PWA instalable (manifest + service worker)
- i18n cobertura 100% (es/en)
- Zero `any` (TS strict)
- RLS activa antes de exponer cualquier tabla
- FX rate snapshot inmutable, never recalculate
**Scale/Scope**:
- Hasta 5000 gastos por workspace
- Hasta 10 miembros por workspace
- 46 functional requirements
- 10 user stories priorizadas P1-P3
- ~25 pantallas

**Structure Decision**: Next.js 15 monolítico con Server Actions reemplazando backend separado. Layered architecture downward-only:
`app/[locale]` (RSC + client islands) → `src/components` → `src/hooks` → `src/actions` (Server Actions) → `src/services` (pure logic) → `src/lib/db/queries` (Supabase reads) → `supabase/migrations` (schema + RLS).

Edge Functions aisladas en `supabase/functions/` para cron jobs y handlers que requieren service role (FX fetch, invitation email). Frontend y "backend lógico" conviven en el mismo monolito; Supabase es la única dependencia externa de runtime.
